# 知識グラフの設計方針

版：v1.1（2026-10-21）

知識グラフは「何を教えるか」を表す、このシステムの土台である。習熟度の記録、出題・推薦、エラー診断、LLM による問題生成は、すべて知識グラフの知識点を単位にして動く。この文書は、知識グラフをどう組み立て、どう管理するかの方針をまとめる。

- 実際の知識点・単元・関係の一覧：`docs/knowledge_graph_overview.md`（YAML から自動生成）
- ファイルの書き方：`docs/content_format.md`
- 知識点・単元・教材を追加する手順：`docs/authoring_guide.md`
- 設計とファイル・出力 JSON の対応、ツールの実装：`docs/tools.md`（§9 に概要）

---

## 1. 構成要素

| 要素 | 何か | 習熟度 | 定義する場所 |
| --- | --- | --- | --- |
| **トピック** | 知識点の置き場所。フォルダ1つと `graph.yaml` 1つ | なし | `content/<トピック>/graph.yaml` |
| **知識点** | 習熟度を記録する最小単位（「できる・できない」を問える単位） | **あり**（解答記録から計算） | 各トピックの `graph.yaml` |
| **単元** | 知識点の集まり。総合演習・トピックをまたぐ練習・テスト範囲に使う | なし（範囲内の知識点から集計） | `graph.yaml` の `units`、または `content/units.yaml` |
| **関係** | 知識点どうしのつながり（4種類、§4） | — | 各トピックの `graph.yaml` |

講義ノートと練習問題は、知識点（または単元）に付ける。

## 2. 層（知識の種類）

研究計画の4層を、次の基準で判定する。**層は「知識の種類」であり、難しさ（難易度 1〜9）や教える順番とは別のもの。**

| 層 | 定義 | 判定の目安 | 主な評価方法 | 例 |
| --- | --- | --- | --- | --- |
| **文法層** | 1つの言語要素が何で、どう動くか | 他の文法を使わずに説明できる | 出力の予測、コードの読解 | `for`、`range`、`break`、`enumerate`、`zip`、内包表記、`def`、`return` |
| **構造層** | 複数の文法要素を組み合わせた、名前を付けられる定番の書き方（**定型パターン**） | 別の場面でもそのまま使い回せる書き方 | 短いコードを書く・穴埋め・バグ取り | 累積、カウント、最大値の更新、フィルタ、探索、辞書による集計、全組み合わせ |
| **アルゴリズム層** | 名前のある、言語によらない完結した手順。正しさや効率を論じられる | 別の言語でも同じものとして通じる | 実装、分析 | 素数判定、ユークリッドの互除法、二分探索、整列 |
| **応用層** | 問題の状況を読み取り、プログラム全体を設計する力 | 問題の分解、パターンやデータ構造の選択が必要 | 仕様文から作る問題 | 仕様から入出力を設計する、処理を関数に分割する、テストで確かめる |

**構造層を「定型パターン」とする理由**

- 初学者が最もつまずくところ。`for` も `+=` も分かるのに「合計を求める」が書けない、ということがよく起きる（プログラミング教育研究の programming plans・Block Model などに対応する考え方）。
- 典型的な誤り（累積変数の初期化忘れ・ループ内での初期化、最大値を 0 で初期化する など）の多くはパターン単位で起きるため、エラー診断（M4）の対応先になる。
- 同じパターンがトピックをまたいで使われる（累積は for にも while にも関数にも出てくる）。

**判定に迷う例**

| 内容 | 層 | 理由 |
| --- | --- | --- |
| `enumerate`、`zip` | 文法 | 1つの言語機能。単独で説明できる |
| `break` と `continue` | 文法 | 1つの言語機能（難易度は高めでも文法層） |
| 「見つけたら break で止める」 | 構造（pat_06 探索） | `for` + `if` + `break` の組み合わせで目的を果たす定番 |
| 文字列中の単語の出現頻度を数える | 構造（pat_07 辞書による集計） | `split`（文法）＋辞書での集計（パターン）。問題はパターンの練習問題になる |
| 二重ループ | 文法 | 「全組み合わせを作る（重複なし）」は pat_08 として別にする |

## 3. トピックと知識点の置き方

1. **知識点はちょうど1つのトピックに属する。** 置く場所は「最初に教える場所」。トピックは置き場所にすぎず、トピックをまたぐつながりは関係（§4）や単元（§5）で表す。
    - 例：変数のスコープは関数の中でしか例を示せないので `func` に置き、変数との概念的なつながりは `related` で表す。
2. **定型パターン（構造層）は専用トピック `pat` に集める。** パターンは本来トピックをまたぐものなので、散らばらせずに一覧できるようにする。その結果、`loop` などのトピックには文法層だけが残る。
3. **粒度の目安**：知識点1つ ≒ 講義 20〜30分 ≒ 練習問題 10問前後。単独で評価できないもの（例：「繰り返しが必要な理由」のような動機づけ）は知識点にせず、関連する知識点の講義に含める。
4. **ID は `トピック_連番`**（例：`loop_03`）。
    - 新しいトピックを作るときは、教える順に `_01` から振る。
    - **一度取り込んだ ID は変えない**（解答記録・習熟度が ID に結びつくため）。既存のトピックに後から知識点を追加するときは、そのトピックの最大の番号の次を使い、表示順は YAML の並び順（または `order`）で調整する。そのため、番号と教える順は後からずれることがある。
    - 知識点の分割・統合は問題の付け替えを伴うので、相談してから行う。

## 4. 関係

| 種類 | 意味 | 向き | 使い道 |
| --- | --- | --- | --- |
| `prerequisite`（先修） | from を習得してから to を学ぶ | あり（循環禁止） | 学習順序、推薦、前提知識の不足の推定 |
| `related_error`（混同エラー） | 混同しやすい・同じ誤りが出やすい | 意味上はなし | エラー診断（M4）、復習問題の選択 |
| `related`（関連） | 概念として同じものの延長・関連（順序には影響しない） | なし | グラフ画面の「関連する知識点」、LLM 診断の文脈 |
| `contains`（包含） | from が to を含む | あり | 現在は使っていない（知識点の大小関係が必要になったときのため） |

- **トピックをまたぐ関係は、後で学ぶ側のトピックの `graph.yaml` に書く。**（例：`col_01 → loop_01` は `loop/graph.yaml`）
- `weight`（0.0〜1.0）は関係の強さ。省略時 1.0。
- 例：
    - 先修 `var_04 → cond_01`（比較演算を知ってから if）
    - 混同エラー `func_03 ↔ io_01`（return と print の混同）
    - 関連 `func_05 ~ var_01`（スコープは「変数」の概念を関数の中に広げたもの）

## 5. 単元

単元は知識点の集まりで、次の用途に使う。

| 用途 | 例 |
| --- | --- |
| **総合演習**（1つのトピックの文法と、関連するパターンを組み合わせる） | `u_loop_for`（for 文の文法 + 基本パターン） |
| **トピックをまたぐ練習** | `u_loop_col`（for 文とコレクション）、`u_func_pat`（関数で書くパターン） |
| **テスト範囲** | `u_midterm`（前半まとめ） |

- **単元は知識点ではない。** 習熟度は記録せず、範囲内の知識点の習熟度から集計する。総合演習の問題の正誤は、その問題に書かれた個々の知識点に反映される。
- 各トピックには、トピック全体を範囲とする単元（ID = トピック名、例：`loop`）が**自動で作られる**。書く必要があるのは、トピックの一部やトピックをまたぐ単元だけ。
    - トピックの一部 → そのトピックの `graph.yaml` の `units`（例：`u_loop_for`）
    - トピックをまたぐ → `content/units.yaml`
- 単元の範囲は `topics`（トピック単位）と `knowledge_points`（個別）を組み合わせて書く。
- 単元に付けられる教材：
    - 講義ノート（例：総合演習のまとめ）
    - 練習ファイル（`unit:` を指定。各問題に知識点を書く）
    - 題単の出題範囲（`selection.units`）
- ID は `u_` で始める（例：`u_loop_for`）。

**総合演習と応用層の区別**：新しい知識を含まず、既存の知識点を組み合わせるだけなら**単元**。新しい技能が必要なら**知識点**（応用層・アルゴリズム層）。たとえば旧「for文 総合演習」の説明には `enumerate`・`zip`・`range` のステップ・文字列のループという新しい内容が含まれていたので、これらは文法層の知識点として独立させ、組み合わせの部分を単元 `u_loop_for` にした。

## 6. 問題と知識点の対応

- 各問題には**知識点を1つ以上**書く。先頭が**主知識点**、2番目以降はその問題で使う他の知識点。
    - 例：`loop_08_q09`（二重ループで2次元リストの合計）→ `loop_08, pat_01`
- 正誤は書かれたすべての知識点の習熟度に反映する（重み付けの方法は M3 の研究課題）。
- 主知識点は、グラフ上での所属・一覧表示・出題範囲の判定に使う。
- 単元の練習ファイルの問題は、主知識点が単元の範囲内にあること（範囲外なら警告）。

## 7. グラフに入れないもの

| もの | 理由 | 扱い |
| --- | --- | --- |
| 教える順番・週ごとの予定 | 同じグラフでも授業によって順番が違う。グラフが表すのは先修関係（半順序）だけ | 将来「コース」ファイルとして別に管理する（`docs/todo.md`） |
| 問題の認知レベル（読む・説明する・書く・直す） | 知識ではなく問題の性質 | 将来、練習問題の属性として追加を検討 |
| 学習者の状態 | グラフは全員共通。習熟度は DB の解答記録から計算する | AI サービスの DB |

## 8. 初期範囲の構成（概要）

変数・入出力・条件分岐・コレクション・繰り返し・関数（文法層）、定型パターン（構造層）、参考として基本アルゴリズム（アルゴリズム層）と問題解決（応用層）。

```
var ─→ io ─┬─→ cond ─┐
           └─→ col ──┼─→ loop ─→ pat ─→ alg
                     │            ↑      ↓
                     └──→ func ───┘  →  app
```

詳細（全知識点・単元・関係、教材の数）は `docs/knowledge_graph_overview.md` を参照。グラフを変更したら `uv run python -m tools.edu_content graph-doc content/ -o docs/knowledge_graph_overview.md` で一覧を更新する。

## 9. 設計とファイルの対応（概要）

| 設計の概念 | 書く場所 | ツールの検証（主なもの） |
| --- | --- | --- |
| トピック | `content/<トピック>/`（フォルダ）と `graph.yaml` の `topic`・`title` | トピック名の重複 |
| 知識点 | `graph.yaml` の `knowledge_points`（ID・タイトル・層・難易度） | ID の重複、層・難易度の値 |
| 関係 | `graph.yaml` の `relations`（トピックをまたぐものは後で学ぶ側のファイル） | 参照先の存在、先修関係の循環 |
| 単元 | トピック内：`graph.yaml` の `units`／トピックをまたぐ：`content/units.yaml`／トピック全体：自動 | 範囲の知識点・トピックの存在、ID の重複 |
| 講義ノート | `lessons/*.ipynb`（メタデータの `knowledge_points` または `unit`） | 参照先の存在、正解・模範解答の混入 |
| 練習問題と知識点の対応 | `exercises/*.ipynb` の各問題の「知識点」（先頭が主）、ファイルの `default_knowledge_point` または `unit` | 参照先の存在、主知識点が単元の範囲内か |

ツールはこれらを検証したうえで、AI サービスが取り込む JSON（`build/json/`）に変換する。出力 JSON の各キーとツールの内部構成は `docs/tools.md` を参照。
